# cortico-world-dream

<img src="assets/icon.png" alt="Dream extension icon" width="128" height="128">

[English](README.md) | 简体中文

一个独立的 Cortico World，提供睡眠、梦境素材采集和可查询的梦境档案。包名为 `cortico-world-dream`，World id 为 `dream`，World API 为 **6**，manifest 包含 `cortico-world` 关键字。宿主需要支持这个接口版本。


梦境事件提示 Coo 调用已有的 `pet_act`，切换睡眠或站立动作，并遵守睡眠期间的回复规则。本 World 控制自己的时限、搜索和记录。动作与回复依赖 Coo 遵守环境提示词；它不会拦截其他 World 的消息。本扩展不直接写入 Memory；可选的「梦话」功能提示 Coo 考虑通过已有 QQ 工具分享梦境。

## 首次启用与更新提醒

在一个部署中首次启用梦境时，向 Coo 投递一次使用介绍。后续版本升级时，投递一次更新事件，包含从上次已通知版本起随包提供的更新摘要。已有 `archive.json` 或 `state.json`、但没有通知记录的部署，收到当前版本的更新提醒。睡眠和梦境任务期间暂缓，清醒且没有梦境任务后投递；不增加页面控件。

提示 Coo 先检查 `dream_status`，再用用户的语言通过本地 `pet_say` 简短说明，不发送 QQ 消息，也不写入 Memory。实际发言依赖 Coo 和可用的本地发言工具。事件按宿主规则保留在会话历史中，不会在每轮环境提示词中重复加入。

`<dataDir>/dream/notice.json` 保存待投递的首次使用分类和上次渲染投递的版本。同版本重新加载或降级不重复提醒。记录表示事件已渲染投递，不代表 Coo 已发言或用户已阅读；保留部署数据重新安装时，该记录继续有效。

## 从本机目录安装

使用 Node.js 22 或以上版本，以及本包声明的 pnpm 版本。在本包目录执行：

```sh
corepack pnpm install
pnpm build
pnpm test
pnpm typecheck
```

1. 打开 Coopanion 的「扩展」页，选择 World，再选择「从本机目录安装」。
2. 选择包含 `package.json` 的本包目录，不要选择 `src`、`dist` 或整个 Coopanion 仓库。
3. 完成安装；安装回执要求重启时，重启 Coopanion。
4. 打开「梦境」World 页面并启用它。无互动后睡眠、定时睡眠和定时白日梦初始均关闭。
5. 打开「素材采集配置」，连接已安装的 ego 浏览器，或保存 Tavily 密钥。ego 可以填写 `ego-browser`、留空从 PATH 查找，或填写可执行文件/应用的绝对路径。「连接并检测」只检查连接，不会将 ego 选为采集方式。网页搜索无需浏览器或 API Key。API Key 只填写到「Tavily API Key」中，不要填写到素材话题、聊天消息或提示词中。
6. 在「睡眠与梦境 → 素材采集」勾选需要使用的方式，通过上移、下移调整优先级并保存。梦境按已保存的顺序尝试采集；全部取消勾选时不采集。

本机安装会链接到这个目录，请保留目录；修改源码后，执行 `pnpm build` 并重启 Coopanion。这不会向 npm 发布内容。

如果曾保存自定义梦境环境提示词，Cortico 会优先使用部署中的覆盖文件。升级不会覆盖它；请在“梦境环境提示词”中参照本包 `src/ENV_PROMPT.zh.md` 合并 `{{dream.index}}`、索引读取规则及群聊与私聊分享规则并保存。没有自定义覆盖时使用新版模板。重启加载新版扩展后，在「系统提示词」点击「立即应用」，或在「World 总览」点击「重载系统前缀」，更新当前会话的上下文。仅保存模板或重启恢复已有会话不会自动重建其前缀。

0.9.0 移除梦境文字窗及其配置入口。已保存的 `overlayEnabled`、`overlayUrl` 和 `overlayElectronFile` 值会被忽略；升级保留部署文件及梦境档案。

## 睡眠与梦境配置

「配置」页包含睡眠、请求超时、结果上限、单次与每日来源上限。「QQ梦话」包含 QQ 指令权限和梦话接收人。「素材采集配置」保留各后端的连接与设置；「睡眠与梦境」提供采集方式勾选和优先级调整，并显示后端状态、睡梦指定素材、白日梦闹钟和档案。

| 配置 | 行为 |
| --- | --- |
| 默认睡眠时长 | 初始为 10 分钟，范围 1–1440 分钟；面板可以覆盖本次睡眠时长。 |
| 无互动后睡眠 | 初始关闭，默认阈值为 30 分钟。符合条件的消息和桌宠触摸事件重置计时；只有桌宠报告已唤醒的触摸才会结束睡眠。 |
| 睡眠做梦模式 | `always` 表示每次入睡都启动梦境；`probability` 表示每次入睡抽取一次概率，取值 0–1，初始为 0.5。同一次睡眠不会反复抽取。 |
| 做梦最长时长 | 初始为 5 分钟，上限 60 分钟。记录完成、取消、超时或唤醒后结束梦境；记录完成后可以继续睡眠。 |
| 定时睡眠 | 初始关闭。填写 `22:30,23:45` 这样的本地时间；每天每个时间点处理一次。 |
| 定时白日梦 | 初始关闭。每个闹钟绑定一个 `HH:mm` 时间和固定公开话题；仅在清醒且没有活动梦境时启动，不会强制入睡。 |
| 授权 QQ 用户 | 初始为空。填写允许控制本 World 的 QQ 号码，以逗号分隔。 |

日期和定时均使用部署配置的时区。进程关闭期间错过的时间点不会补执行；重启后仍有效的睡眠时限会继续，中断的梦境不会重新启动或重新抽取概率。

可直接发送 `睡觉十分钟`、`睡觉 30 分钟`、`sleep 10 minutes`、`睡觉` 或 `sleep`；不写时长时使用配置值。`醒来`、`起床` 和 `wake up` 可以提前唤醒。更宽泛的自然语言表达依赖 Coo 调用工具。

桌宠对话框和设置中的普通聊天会唤醒 Coo，并取消当前梦境。触摸只有在桌宠事件报告 `meta.touch.woke === true` 时才结束睡眠或梦境；其他触摸只重置无互动计时。桌宠 World 会合并连续触摸，通常在最后一次触摸约 2.5 秒后发布事件，因此梦境状态可能比动画稍晚收到唤醒信息。

QQ 普通消息不会自动唤醒。只有「授权 QQ 用户」中的账号，在私聊或群聊 @Coo 时明确要求醒来，才允许唤醒。自然语言 QQ 唤醒请求需要 Coo 确认其含义，再调用带 `explicitWakeRequest: true` 的 `dream_wake`；单独 @ 不算唤醒请求。睡眠时，任何人在群中直接 @Coo，包括仅 @ 而未要求唤醒的授权用户，最多得到一句「呼，呼…」这样的睡眠短语，不结束睡眠，也不讨论消息话题。

基础版 QQ 只提供渲染后的自我提及标记，因此采用兼容回退，无法验证原始 @；Final 与 ProMAX 提供来自实际提及段的 `atMe`。「授权 QQ 用户」是本 World 的指令白名单，不是当前登录 QQ 账号，也不会从 Memory 中的“主人”设置自动同步。本 World 不读取 Memory 文档推断权限。

自然语言请求通过 `dream.message_ref` 向 Coo 提供原消息的 `eventCursor`。引用将原话与内部编号绑定，QQ 消息还附带平台 `messageId` 便于对应；它不认定消息一定是睡眠指令，由 Coo 判断意图后调用 `dream_sleep`、`dream_wake` 或 `dream_add_material`。只引用本次启动后收到、距今不超过五分钟且符合现有权限和会话要求的消息；固定格式的睡眠、唤醒命令仍自动处理。引用包含用户原话，以外部内容投递，不复制控制台 PIN 或附件，也不写入梦境档案或 Memory。工具执行时重新校验原消息；QQ 平台消息号、引用事件自身编号、过期或重启前的编号均不能代替有效的原消息编号。提示词要求 Coo 将原消息与引用作为同一条消息处理，不因引用额外回复。

睡眠中的本地自然语言请求会先按普通消息规则唤醒 Coo。若 Coo 随后将同一条消息理解为新的睡眠时长，仍可用它的引用调用 `dream_sleep`；出现较新的用户交互或睡眠状态操作后，该例外失效。工具重试不会延长已经执行的睡眠。

## 指定素材与梦境档案

在「指定素材」中为睡梦添加公开话题或公开链接，也可以在符合条件的聊天中请 Coo 保存话题。聊天添加使用 `dream_add_material`，并携带原消息在事件库中的游标。每条话题最多 500 个字符，标签为 `指定素材`，长期保留，直到在面板中删除。

提示词要求 Coo 优先处理部署本地日期内尚未检索的指定素材，再自行选择热点。携带素材 id 的 `dream_search` 或 `dream_ego_read` 成功返回非空结果时，记录该素材当天已处理；官方 WebSearch 在 `dream_web_search_result` 成功接受本次请求的来源时标记。空结果和失败不会标记，其他 ego 动作也不会标记。优先顺序由 Coo 按提示词执行，World 负责记录处理日期。

在「白日梦闹钟与素材」中单独填写时间和公开话题。话题必填、最多 500 个字符，长期保留，每次闹钟触发都重新围绕该话题采集；同一时间只能有一个闹钟。白日梦没有“今日已处理”标记，也不借用睡梦指定素材。在「配置」中启用定时白日梦后，到睡眠面板添加或编辑闹钟。

Coo 先调用 `dream_search` 登记公开查询词，以及可选的睡梦 `materialId`。Tavily 和网页搜索直接返回来源；ego 返回 `needsBrowser` 后，由 Coo 交互浏览并通过 `dream_ego_read` 登记来源。提示词要求每次梦境选择一个主题，在配置上限内采集多篇相关新闻，再通过 `dream_record` 传入标题、梦境正文和返回的来源 id。标题由 Coo 根据完整梦境概括核心场景或意象，最多 80 个字符；正文最多 6000 个字符。记录保留标题、正文、来源标题/网址/摘录、素材 id 和时间戳。梦境是虚构档案，不作为真实经历写入 Memory。

环境提示词、`dream_record` 说明和完成事件要求梦境正文、来源及处理进度只通过梦境工具保存；禁止为本次梦境、采集过程或素材处理状态调用文件工具追加 `notes.md` 或其他记忆文件。保存成功后结束本次任务；梦话分享由独立的 `dream.share` 事件触发。

点击梦境标题可以展开或收起记录；面板保持打开时，状态刷新和档案搜索会保留各条记录的展开状态。面板展示最近 30 条匹配记录，查询包含标题；`dream_query` 最多返回 50 条带标题的摘要，`dream_read` 读取一条完整记录。

环境提示词变量 `{{dream.index}}` 以 JSON 数组提供最近保存的最多 10 条梦境，新记录在前。每个条目只包含 `id`、按部署时区计算的 `YYYY-MM-DD` 日期 `date` 和已有的 `title`；档案为空时返回 `[]`。Coo 将这些标题视为虚构档案数据，需要详情时携带条目的 id 调用 `dream_read`，索引之外的记录通过 `dream_query` 查询。

Cortico 重建环境前缀或预览提示词时，World 从自己的档案生成索引。保存或删除记录会反映在下一次生成的索引中。普通模型请求复用当前会话前缀，不会逐次刷新索引。索引只存在于运行时内存和模型上下文，不创建额外文件，也不写入 Memory。

使用记录的删除按钮并确认，会在一次档案写入中删除该记录和关联分享提示条目。删除不退回采集计数，不删除指定素材或闹钟，也不能撤回已有事件、模型上下文、QQ 草稿或已发送消息。

已有 version 1 档案继续兼容。没有标题的旧记录使用简短正文摘录，并标记为 `titleSource: "legacy-excerpt"`，正文和来源保持完整，缺失的梦境种类仍为未知；新梦境由 Coo 拟定的标题标记为 `titleSource: "summary"`。兼容字段在下次档案写入时保存，不为补标题发送模型请求。升级后适用下方的保留规则。

升级到 0.7.0 时，旧 `daydreamTimes` 一次性迁移为话题留空的闹钟；填写话题后才能触发，已删除闹钟不会从旧配置重建。原指定素材保留，仅用于睡梦；历史梦境不会自动加入分享队列。

另一 World 可以发出事件，提示 Coo 调用 `dream_query` 和 `dream_read`，再决定是否主动发起讨论。组织上下文或记忆查询的流程也可以提示调用这两个工具。本包不会添加这个主动会话 World，也不会修改现有 Memory 扩展。

## 档案保留、引用计分与深层梦境

0.12.1 起，普通梦境按现实时间保留 **30 × 24 小时**，最多 **100 份**；恰好满 30 天的记录保留，超过后清理。启动时、运行期间每分钟、档案工具读取前以及新增档案时检查。先删除过期的普通梦境，再按创建时间删除最旧的普通梦境，直到不超过 100 份。深层梦境不参与两项限制；两类记录都支持手动删除。

继续使用 `dream/archive.json`，每份记录增加 `score`、`tier`（`ordinary` 或 `deep`）和可为空的 `promotedAt`。旧记录兼容为普通梦境、0 分，正文和来源在触发保留规则前保持不变。清理同步移除对应采集来源、分享状态和计分去重项，保留用户指定素材、白日梦闹钟及已消耗的采集额度。已发送的聊天消息和已有模型上下文无法撤回。

「配置 → 梦境档案 → 深层梦境阈值」默认 **3**，可填写 0–1000 的整数。每次新计分后，分数严格超过阈值才晋升，默认第 4 次有效引用后成为深层梦境。修改阈值在下次有效计分时生效；晋升后保持深层分类，提高阈值不降级。`dream_query`、`dream_read` 返回分数及分类，仍可检索深层记录；档案标题旁的「深层梦境」标签在折叠和展开时均显示。

计分支持有可验证发送记录的**基础版 QQ、ProMAX 与桌宠回复**；Final 0.6.33 缺少此类记录，暂不支持计分。Coo 因当前话题读取旧梦时，调用 `dream_read({id, replyTo})`：QQ 的 `replyTo` 提供来信 `source`（`qq` 或 `qqbot`）、平台 `messageId` 及可选的 `target`（`group:<id>` 或 `private:<id>`）；桌宠提供 `source: "desktop-pet"` 和 `dream.message_ref` 中的原消息 `eventCursor`。来信必须在五分钟内、早于读取且晚于梦境创建。读取返回有效期五分钟的 `usage.usageToken`，此时不加分。Coo 实际发送回复后，再调用 `dream_mark_used({id, usageToken, reply})`：QQ 提供 `qq_confirm` 或 `qq_send` 成功回执中的已发送 `messageId`；桌宠提供完整可见回复 `text`，拼接各段文字并去除动作标记。

World 核对读取后同一会话中的实际输出记录。基础版 `qq.self` 与 ProMAX 中 `delivery: "confirmed"` 的 `qq.sent` 表示 API 发送成功。ProMAX 计分要求 `textOnly: true` 且正文非空的纯文字回执，不核验图片、语音或合并转发输出；桌宠证据表示已接受发言，不代表播放完毕或用户已读。话题相关性及回复是否确实引用该梦由 Coo 判断。桌宠异步记录尚未落库时，可以稍后重试计分报告，不为计分重新发送回复。普通查询、读取、生成梦境、发送失败、草稿、QQ 空间发布和自动 QQ 梦话分享均不计分。来信与输出之间若出现同一梦境、同一目标的自动分享建议，因归属不明确而拒绝计分。控制台目前不能核实投递，暂不计分。QQ 发言者无需拥有睡眠指令权限，其真实话题也可触发旧梦引用。

同一条回复对同一份梦境最多加一次；同一档案内的 `usageReceipts` 只保存回复标识用于去重，不复制聊天正文。准备凭证只在内存中保存，五分钟后、入睡、开始白日梦或重启时失效。加分和保存去重标识在同一次原子写入完成。已有自定义梦境环境提示词时，请从 `src/ENV_PROMPT.zh.md` 合并保留和引用计分规则，再重载系统前缀。

## 可选 QQ 梦话

梦话需搭配 QQ 插件使用，默认关闭。在「QQ梦话」中单独保存指令权限（`qqUsers`），开启 `dreamTalkEnabled`，再向 `dreamTalkGroups` 添加群号或向 `dreamTalkPrivates` 添加私聊 QQ 号。梦话接收人不获得睡眠指令权限。睡梦完成后等待 Coo 醒来；白日梦完成且当前没有睡眠或梦境时，即可提供分享建议。

群号和私聊号码下拉框通过基础版 QQ 的公开名单面板读取已启用的监听号码。Final 与 ProMAX 的接收人可通过「添加自定义」填写；读取到名单不代表 QQ 已连接。页面只请求名单中的号码和启用状态，不读取账号凭据、联系人名称或消息，也不修改 QQ 自身的名单。添加、修改、删除和分享开关即时保存；指令权限通过「保存指令权限」生效。保存失败时保留填写内容以便重试。

每份待分享记录从两类白名单中随机推荐一个群或一位私聊用户，并向 Coo 提供一次建议。Coo 调用 `dream_read` 查看档案，结合该会话上下文判断是否适合分享，也可以跳过。发送流程按当前可用工具选择：基础版使用 `qq_draft` → `qq_confirm`；Final 与 ProMAX 根据当前工具参数声明，使用 `qq_send({to, text, ...})` 直接发送。只有回执明确要求确认旧草稿时，才需要 `qq_confirm_send`。Coo 在实际发送前检查睡眠状态、接收人权限和新消息。各 QQ World 保留自己的目标校验，自定义梦话接收人不绕过这些校验。发送成功或结果未知时都不重复发送。一次建议只代表已提示 Coo，不代表消息已送达，也不授权更换接收人或群发。

待提示状态跨重启保留；恢复时检查已持久化的通知事件，避免重复建议。关闭梦话或清空两类接收人名单会清除待提示条目；移除已选择的接收人会丢弃对应的待提示建议。重新开启不补发历史记录。删除梦境会清理其提示条目，但不能取消其他 World 已创建的 QQ 草稿或消息。升级到 0.11.0 保留原有指令权限、群名单及待提示群建议，新增私聊名单默认为空；QQ 配置从「配置」移至「QQ梦话」，已有存储键不改名。

## QQ 版本兼容

适配以每次单独启用一个 QQ World 为前提。Final 和 ProMAX 的梦境控制与分享无需额外启用基础版；`qq-all` 不作为独立梦境渠道。

| QQ World | 睡眠、唤醒及公开素材指令 | 群聊／私聊梦话分享 | 引用计分 |
| --- | --- | --- | --- |
| 宿主附带的基础版 QQ | 可验证的单条 `qq.message` | `qq_draft` → `qq_confirm` | 成功的 `qq.self` 记录 |
| [Final 0.6.33](https://github.com/hth768/cortico-world-qq-final/tree/00a1f15e85f71b22590c60e8beeab8a570cb74b7) | 可验证的单条 `qqbot` 消息 | `qq_send` 直接发送 | 暂不可用：当前版本缺少发送成功事件 |
| [ProMAX 0.2.0](https://github.com/Kpect10086/QQ-ProMAX/tree/360e37f5b83c2e0479069dd8886bc029c56ab732) | 可验证的单条 `qqbot` 消息，包括核对原消息后的延迟投递 | `qq_send` 直接发送 | 已确认的 `qq.sent`；撤回证据不明确时拒绝计分 |

所有控制路径都要求可验证的发送者、平台消息号和群聊／私聊会话。适配层保留 ProMAX 延迟消息的原时间与游标，按平台消息标识去重；历史回填、自己发出的消息和重复投递不能重新执行睡眠指令。Final 与 ProMAX 的私聊聚合把多条正文合并到一个消息号下，不能据此授权控制或引用计分。需要这些单条消息功能时，保持两者的 `privateAggregationWindow` 为 `0`。缺少的元数据不会根据文本中的身份声明补全。 已知撤回的请求不能继续使用；qqbot 撤回记录缺少必要信息、无法排除当前请求受影响时，也拒绝延迟控制。

Final 需要提供持久化的发送成功事件，包含会话、平台消息号、正文和确认送达状态，梦境才能核验计分。两种扩展的撤回事件均缺少被撤回消息的编号；相关撤回无法对应到具体消息时，梦境拒绝计分报告。计分完成后发生的撤回不追溯扣除已有分数。共用的 `qqbot` 来源本身不能证明这些能力。

QQ 空间动态、评论、自动发文请求和发布回执不参与聊天控制或计分。梦话只向已配置的群和私聊目标分享；QQ World 的独立空间功能及睡眠期间发说说的规则仍由该 World 管理。 ProMAX 0.2.0 在未显式调用发送工具时可能转发最终回答，因此梦境提示词同时要求静默任务不输出最终回答播报。

自动兼容测试在真实事件存储中使用符合这些公开结构的合成消息，不连接 QQ 网络。真实 QQ 与空间行为仍需在隔离测试部署中人工检查。已有自定义环境提示词时，需要从 `src/ENV_PROMPT.zh.md` 合并发送流程与计分规则，再重载系统前缀。

## 素材采集方式

「睡眠与梦境 → 素材采集」分为「内置」与「World 扩展」：内置包含 ego、Tavily、网页搜索；World 扩展包含「官方 WebSearch（由 Coo 调用）」。编号表示两类方式共用的优先顺序，上移和下移可跨分类调整顺序。官方 WebSearch 默认不勾选。0.12.0 保留已有 `collectorOrder` 值，勾选新方式时才向同一数组加入 `websearch`。

梦境轮到官方 WebSearch 时，由 Coo 检查工具是否可用。该项状态显示「由 Coo 检查工具」，本地配置齐全不代表已安装或能够使用 `web_search`。DeepSeek、Brave 等提供商及密钥在官方 World 中配置，以已安装版本支持的选项为准；梦境不读取这些配置，也不自动发现工具列表。

侧栏提供一颗「素材采集配置」灯。绿色表示已勾选的后端中至少一种必要配置已齐全，灰色表示没有满足条件的采集方式。各后端的状态点表示配置是否齐全，「当前使用」另行标注当前后端。这些状态不证明密钥有效、浏览器已连接或搜索成功；悬停说明和连接结果显示缺少的配置及错误。

「素材采集配置」包含 ego、Tavily、网页搜索三个可展开区域。默认展示 ego 路径及旁边的「连接并检测」按钮，以及 Tavily API Key 输入框。ego 展开后包含 Space 与连接配置、连接状态及辅助进程操作。修改「截图时恢复最小化窗口」等配置后，点击「保存配置」生效。采集方式及优先级只在「睡眠与梦境 → 素材采集」选择；通用上限在「配置」页修改。API Key 作为密钥保存，不会返回给面板。

| 采集上限 | 默认值与行为 |
| --- | --- |
| 单次梦境最多采集条数（`maxSourcesPerDream`） | 默认 5，整数范围 1–20；同一次梦境内的所有采集调用共同使用。 |
| 每日最多采集条数（`maxSourcesPerDay`） | 默认 20，整数范围 1–1000；按成功登记时的部署本地日期，累计当天各次梦境的来源。 |

上限统计成功登记且文字非空的来源。同一次梦境内，网址规范化并移除 `#` 片段后去重；重复读取或分页读取同一网址会复用来源 id，不增加条数。在下一次梦境重新采集该网址会再次计数。网页搜索的每个有效结果网址及摘录登记为一条来源。空结果、失败和连接测试不计入上限。这些数值限制来源条数，不是网络请求次数或服务费用上限。

睡眠面板以细进度条显示本次和今日采集用量：彩色部分表示已登记来源，灰色部分表示剩余额度，同时标注已采集、剩余及上限数量。上限调低到已用量以下时，进度条显示全满、余量为零，仍显示实际已采集数量。每日计数跨重启保留；唤醒、取消或未保存梦境不会退回已经登记的条数，过去日期的计数也会保留。达到上限时，Coo 可以使用已有来源完成梦境；当天额度用尽后，不启动新的梦境。旧部署缺少这两项配置时使用默认值；没有 `collectionCounts` 的 version 1 档案从零开始计数，不追溯计算历史梦境。

睡眠面板显示当前阶段、采集结果、已尝试的方式及各后端状态。当前阶段包括「清醒」「睡眠」「等待 Coo 调用」「正在采集」「正在生成梦境」；白日梦在进度前显示「白日梦」，例如「白日梦 · 正在采集」。「等待 Coo 调用」表示当前梦境正在等待 Coo 调用采集工具并取得素材；「正在生成梦境」表示素材已返回，World 正在等待 Coo 编写并保存梦境，不表示已确认模型请求正在运行。采集结果显示最近一次成功返回非空结果的梦境采集时间，或本次采集失败原因。这些状态保存在当前 World 实例的内存中，重启 World 后重置。

「测试采集连接」只保留在「素材采集配置」页。它要求启用 World，只测试顺序中首个已勾选且保存配置齐全的后端，不自动尝试下一种方式，也不修改选择。ego 测试连接梦境 Space 并检查控制状态，不导航或搜索；Tavily 和网页搜索使用 `current public news YYYY-MM-DD`，日期采用部署本地日期。Tavily 的有效空响应可以证明连接成功；网页搜索的所有引擎均未返回可用摘录时，测试失败。测试返回后端及诊断结果，不依赖 Coo 调用工具，不登记来源、不占用来源额度、不处理指定素材、不建立梦境记录，也不更新最近成功梦境采集时间。Tavily 测试可能计入账号使用量。

### 连接 ego

1. 单独安装并打开 [ego-lite](https://github.com/citrolabs/ego-lite)，完成初始设置，并在 Coopanion 中启用梦境 World。
2. 在「素材采集配置 → ego」保留 `ego-browser`，或留空从 PATH 查找。也可以填写可执行文件的绝对路径，macOS 支持 `.app` 路径。点击「连接并检测」会展开连接详情，不改变已勾选的采集方式或顺序。
3. 扩展为当前部署建立或重新连接一个梦境专用 Space，显示名称/id、实际连接途径及连接状态。连接进度、可用状态和错误显示在 ego 展开配置的上方。连接失败后立即刷新面板，显示错误码和原因；缺少错误码时明确显示原因未知。重复连接复用这个 Space。ego 使用自己的默认 Profile，不再提供 Profile 选择。

默认 Profile 可能与梦境 Space 共享已有登录状态。提示词要求 Coo 只采集公开素材，不读取私人账号数据、凭据或个人信息，也不发布内容、购买或更改账号。Space 限定浏览器操作的归属，不是独立 Cookie 存储。页面文字和截图可能进入宿主配置的模型上下文；请在适合此用途的浏览器环境中使用 ego。

| ego 配置 | 默认值与行为 |
| --- | --- |
| Space 名称 | 留空时按部署生成独占名称。不同部署不要共用名称或辅助进程目录。 |
| 请求超时 | 45,000 毫秒，范围 5,000–120,000 毫秒。 |
| 快照文字上限 | 16,000 个字符，范围 1,000–60,000。 |
| 恢复最小化窗口 | 页面截图时默认启用。 |
| 连接方式 | `auto`、`direct` 或 `helper`。`auto` 先尝试 CLI 直连，仅在 ego 执行前拒绝高权限客户端时，改用已运行的普通权限辅助进程。 |
| 辅助进程目录 | 留空使用 `<dataDir>/dream/ego/helper`；自定义值必须是当前部署专用的绝对路径。 |

辅助进程是可选方式。「生成助手启动脚本」只写入启动文件并显示绝对路径，不启动进程。macOS 用户需要在普通用户会话中自行打开 `start-ego-helper.command`，确保 PATH 上可以找到 Node.js 22 或以上版本，再重新连接。Windows 使用 `start-ego-helper.cmd` 及配套 PowerShell 文件。「停止助手」停止本部署的辅助进程；不要以 root/管理员权限启动它。

0.8.1 使用辅助进程协议 3。已有普通权限辅助进程正在运行时，需要先停止，重新生成启动脚本并启动，再连接；协议 2 的旧辅助进程不兼容。直连方式无需辅助进程。

配置面板不提供手动交接或恢复控制按钮，由 Coo 在梦境 Space 中执行日常采集。ego 报告用户控制、浏览器权限提示或结果不确定时，梦境扩展暂停浏览操作，并按照已选后端顺序继续采集，不抢回控制权、不关闭权限提示，也不重放结果未知的动作。[ego 的公开控制接口](https://github.com/citrolabs/ego-lite/blob/d392204d1ea1a8027a591ab2b0129c2e11d85f26/package/ego-browser/src/ego-errors.ts)要求浏览器权限提示由用户处理，没有提供在 Space 暂停时自动拒绝的受支持接口。

对于现存 Space，只有元数据和 SDK 只读控制检查均确认 agent 控制，才会清除可恢复的本地暂停状态。这可以检测你在 ego 中交回的控制权，也可以在结果不确定的操作之后恢复本地可用状态，不调用接管或认领接口。最近一次未知结果仍以 `lastUnknownOutcome: { operation, code }` 保留在连接状态、`dream_status.browser` 和采集回执中；恢复可用并不证明该操作已成功。旧的不确定状态没有原始操作名称时，使用 `operation: "unknown"`。Coo 继续前需要检查当前页面，不得重放结果未知的动作。

Space 检查使用已保存的 id，并核对名称；没有 id 时，要求配置的梦境 Space 名称只有一个匹配，不创建 Space。连接到已交给用户控制的现有 agent Space 时，保留其 id 并报告采集暂停，后续检查才能识别交回的控制权。真正属于用户的 Space 视为名称冲突，不会认领；此时应配置独立的梦境 Space 名称。身份不存在、重复或不匹配都不构成接管授权。操作结果不确定且随后发现 Space 缺失时，不创建替代 Space；已确认 Space 缺失且未处于结果不确定的暂停状态时，后续连接可以建立新的梦境 Space。

已越过 ego 的当前梦境不会回头使用它；恢复可用后，后续梦境可以使用 ego。保存采集配置、重新连接、生成或停止辅助进程都会取消当前梦境，并保留睡眠截止时间；下一次梦境采用保存后的采集顺序。

唤醒、取消或停止 World 会取消本 World 的待执行任务，阻止旧梦境后续操作与写入。Space 和页面保留，供检查和复用。已发送给浏览器的动作仍可能完成，取消不能撤回它。本包不包含 ego-lite，需要单独安装。

### ego 浏览工具

在活动梦境的当前采集方式为 ego 时，Coo 可以调用 13 个带前缀的工具：`dream_ego_open`、`navigate`、`tabs`、`read`、`click`、`fill`、`press`、`scroll`、`evaluate`、`wait`、`shot`、`close` 和 `handoff`（每个名称均以 `dream_ego_` 开头）。工具仅操作梦境专用 Space。页面动作返回快照和受管理的页面标签；元素引用应取自新快照。只有 `dream_ego_read` 将非空文字登记为 `dream_record` 可用的来源。

ego 没有固定搜索网站，由 Coo 选择公开 HTTP(S) 页面并操作浏览器界面。显式网址拒绝凭据和已知本机/私网地址；该验证不属于浏览器级网络过滤。`evaluate` 运行页面 JavaScript，不提供 Node 或文件系统 API。`shot` 返回不超过 8 MiB 的页面视口图片，需要支持视觉的模型解读，不截取桌面。未包含视频及 Bilibili 专用工具。

### 采集选择与搜索

使用 `websearch` 时，`dream_search` 返回 `needsWebSearch`、公开查询词、当前额度及 `requestId`。Coo 检查当前可用工具，按官方 `web_search` 的声明调用，再将实际返回的标题、公开 HTTPS 网址及摘录，连同 `cycleId` 和 `requestId` 交给 `dream_web_search_result`。World 分配可用于 `dream_record` 的来源 id，按不同网址计数，仅在成功接受来源后标记睡梦指定素材已处理。来源标记说明内容由模型从 `web_search` 转录；梦境不独立核实官方工具的返回值。每份回执仅接受一次报告，继续查询时重新调用 `dream_search`。

工具不存在、搜索失败或结果为空时，分别报告 `failure: "unavailable"`、`"failed"` 或 `"empty"`，由同一次梦境继续后续已选方式。唤醒、过期或新的查询会使旧报告失效；梦境不能保证取消其他 World 中已执行的官方工具。「测试采集连接」无法运行此方式，会显示由 Coo 检查工具的说明。已有自定义梦境提示词时，请从 `src/ENV_PROMPT.zh.md` 合并这些规则，再重载系统前缀。

保存的 `collectorOrder` 数组是唯一的采集选择。例如 `["ego", "tavily", "browser"]` 依次尝试 ego、Tavily、网页搜索，`[]` 表示不采集。每次梦境保留启动时的顺序，遇到方式不可用、失败或搜索没有可用来源时向下尝试，不回头使用之前的方式，不重新开始睡眠，也不重置来源额度。所有方式共用本次梦境时限及来源上限。已选方式全部尝试完毕后，有已有来源时 Coo 可以据此保存梦境；没有来源时跳过本轮，不请求人工协助，也不编造素材。

先调用 `dream_search`，可以在 ego 浏览前登记公开查询词及可选的睡梦 `materialId`。ego 受阻后，World 使用已登记的查询词自动运行后续方式。旧流程若直接调用 ego、尚未登记查询词，需要查询词才能继续时会返回 `needsSearch`，由 Coo 围绕同一主题调用 `dream_search` 续作；不得从错误或私人页面推断查询词、抢回控制权或要求用户恢复 ego。

升级到 0.8.0 时，`collectorOrder` 为 `null` 会从旧选择迁移一次：原 `auto` 在 `egoEnabled` 为 true 时变成 `["ego", "tavily"]`，否则为 `["tavily"]`；原明确选择 `ego` 时，启用则为 `["ego"]`，关闭则为 `[]`；原明确选择 `tavily` 或 `browser` 时，保留为对应的单项列表。迁移后，旧 `backend` 和 `egoEnabled` 不再决定采集选择。已有密钥、ego 路径和 Space 配置保留。旧 `egoProfileId`、Chrome 可执行文件路径、搜索网址和域名配置仍保留存储，但采集不读取或使用；已有 `dream/browser-profile/` 目录既不读取也不删除。无需安装 Chrome。

| 方式 | 采集内容 |
| --- | --- |
| `tavily` | 向 `https://api.tavily.com/search` 发起最近一天的新闻搜索，保留返回的摘录、标题、链接及存在时的日期；不请求原始网页、生成答案或图片。 |
| `ego` | 通过已安装的 `ego-browser nodejs` API，在专用梦境 Space 中交互浏览公开页面、读取快照及页面截图。 |
| `browser` | 网页搜索：拼接固定公开搜索网址，通过 HTTP 读取 HTML/RSS 中的结果标题、链接和摘录；无需 Chrome、Profile 或 API Key。 |
| `websearch` | Coo 调用官方 `web_search`，将返回的公开来源摘录交给梦境登记。提供商选择、网络请求及凭据由官方 World 管理。 |

网页搜索参考 [cortico-world-netlingo](https://github.com/danhuangpaii/cortico-world-netlingo/tree/38fea2eed308fc3a1f4865312d53a582b98279bf) 的网址拼接和结果解析方式。对同一查询词进行 URL 编码，依次尝试以下固定地址，取得第一组可用结果后停止：

1. `https://www.so.com/s?q={query}`
2. `https://www.sogou.com/web?query={query}`
3. `https://www.bing.com/search?format=rss&q={query}&count=10`
4. `https://html.duckduckgo.com/html/?q={query}&kl=cn-zh`

HTTP 错误、超时、响应过大或没有有效摘录时，继续下一引擎。每个引擎最多使用 12 秒或配置的请求总超时的四分之一，取两者较小值；整次搜索也受该总超时限制。响应上限为 512 KiB，每条摘录最多 12,000 个字符。解析器只接受有标题、非空摘录且使用公开 HTTPS 域名的网址，拒绝凭据和自定义端口。它不访问结果链接、不执行脚本、不加载页面资源，也不读取浏览器 Profile；搜索端点的 DNS 地址需通过公网检查，重定向一律拒绝。搜索引擎 HTML 改版、人机验证或登录要求可能导致该方式不可用。

Tavily 和内置网页搜索的默认总超时为 30 秒，每次调用最多返回 5 条结果。搜索结果可能没有发布日期，Coo 需要判断是否符合所需日期；Tavily 的「最近一天」也不保证每条结果都在今天发布。唤醒、取消或停止 World 会中止梦境自身执行的采集，不再尝试下一个引擎或后端，并阻止旧梦境写入。来源文字和浏览器动作回执是不可信数据，不能作为操作指令。ego 进程只接收最少的运行环境，不接收 Tavily 凭据。

## 数据、文件与网络访问

| 位置或连接 | 用途 |
| --- | --- |
| `<部署 dataDir>/dream/archive.json` | 睡梦话题及处理日期、白日梦闹钟、梦境标题/正文/来源/分数/分类、分享状态、计分回复标识及每日采集计数；单文件原子保存，普通梦境适用 30 天／100 份保留限制。 |
| `<部署 dataDir>/dream/state.json` | 睡眠截止时间及定时执行日期。 |
| `<部署 dataDir>/dream/ego/state.json` | 跨重启保存专用 Space 身份、暂停/结果不确定状态及最近一次操作的未知结果。 |
| `<部署 dataDir>/dream/ego/rounds/round-*` | 每次调用的 `script.mjs`、`result.json` 和可选 `page.png`；成功、失败或取消后删除。 |
| `<部署 dataDir>/dream/ego/helper/` 或配置的辅助进程目录 | 启动文件、`helper.stdout.log`、`helper.stderr.log`，以及运行期间的 `endpoint.json`/`.helper.lock`。辅助进程调用使用其 `ego/rounds/round-*` 子目录，每次调用结束后删除。 |
| `<部署 dataDir>/dream/browser-profile/` | 如果存在，保留旧 Chrome 目录，不读取或删除。 |
| `<部署目录>/worlds/dream/ENV_PROMPT.en.md` 或 `ENV_PROMPT.zh.md` | 通过 Cortico 提示词编辑器保存的可选部署覆盖。 |
| 部署目录的 `.env` | Cortico `storeSecret` 保存 `CORTICO_DREAM_TAVILY_API_KEY`，文件权限仅允许所有者读写。面板只显示是否已配置。 |
| 已安装 ego 应用/CLI 及默认 Profile | 定位并执行 CLI，管理梦境 Space/页面；默认 Profile 可能与这些页面共享登录状态。 |
| 部署配置 | 保存 `collectorOrder`、ego CLI 路径、Space 名称、连接方式及其他非密钥配置；迁移后保留但忽略旧选择及 Chrome 字段。 |
| Cortico 事件库 | 新收到的符合条件的消息/触摸，用于计时、权限及取消任务；不将聊天记录复制到档案。 |
| `https://api.tavily.com/search` | 发送梦境或连接测试的查询词，以及用于该请求身份验证的 Tavily 凭据；密钥不会传给浏览器方式或写入梦境记录。 |
| Coo 选择的公开网站 | 活动梦境期间 ego 的页面导航、公开搜索交互及页面资源请求。 |
| `https://www.so.com/s`、`https://www.sogou.com/web`、`https://www.bing.com/search`、`https://html.duckduckgo.com/html/` | 按优先级接收梦境或连接测试公开查询词的固定搜索端点，不发送 API Key 或浏览器 Cookie。 |
| 辅助进程的本机 HTTP 端点 | 当前部署向可选辅助进程发出的已认证本机请求。 |

新目录使用 `0700` 权限，档案/状态文件和 ego 脚本/结果文件使用 `0600`。档案/状态通过临时文件进行原子替换。ego CLI 导入每次调用的独立 `script.mjs`，通过 JSON 文件返回结果，控制台输出不用于传递结果。macOS 辅助进程启动文件使用 `0700`，日志仅所有者可访问；端点/锁文件使用 `0600`，在对应辅助进程退出时删除。启动文件和日志保留，供复用与诊断。

本扩展不扫描个人文件或 Memory 文档。浏览工具限定在梦境 Space 内，提示词要求 Coo 只处理其中的公开素材。公开话题、来源摘录、快照、请求的页面图片和梦境文字会提供给 Coo 的上下文，后续处理遵循宿主配置的模型服务设置。页面截图是临时传输文件，不存入梦境记录。

安装依赖时会访问所配置的 npm registry。新闻采集发生在活动梦境或 Tavily/网页搜索连接测试中。来源与许可证见 [NOTICE.md](NOTICE.md)，其中注明了本扩展改编使用的 MIT 许可 ego 实现和 Netlingo 搜索解析器。

## 开发检查

`pnpm test` 执行 World、采集适配器、档案和面板的离线测试。`pnpm typecheck` 检查 Node/浏览器代码，`pnpm build` 构建面板和 `dist/ego-helper.mjs`。辅助进程加载包内的 `src/ego-runtime.mjs`，安装时需要保留 `src` 和 `dist`。这些检查不代替对所选新闻服务及已安装浏览器的手动试用；测试不需要真实账号或已安装 Coopanion 的数据。
